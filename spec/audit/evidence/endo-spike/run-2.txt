# The ERTP round trip against a **node** — issue #249, clause 4, met.
#
# command: node ertp-round-trip.mjs 22050          (script: ertp-round-trip.mjs, in this directory)
# node:    target/debug/rnode run --data-dir <dir>, configured by `node.conf` in this directory
#          (dev-mode, a bonded validator, propose-on-deploy, an OCapN listener on 127.0.0.1:22050)
# peer:    @endo/ocapn 1.1.1 on Node v22.22.2, framing 'syrup'
#
# The clause reads "a peer implementation fetches an RChain issuer over OCapN and the round trip is
# demonstrated". The earlier spike (`run-1.txt`) dialled the standalone fixture binary and fetched
# the *echo* fixture, so nothing ERTP ever crossed and the clause was **not** met; this run is what
# meets it. What the script does, in order:
#
#   fetch the ERTP contract → makeIssuerKit → hold the brand/mint/issuer → makeEmptyPurse on the
#   issuer → read that purse's balance
#
# and the last line is the answer of a *live ERTP purse on chain*: `[ true, 0n ]`, the Rholang pair
# `(true, 0)` as a Syrup list, after a deploy, a block, and a registry lookup on the way back.
#
# Three things this run found, all now fixed (they are the reason the transcript is kept rather than
# summarised):
#
#  * **`insertSigned` cannot register a returned capability.** It derives the URI from the *deployer*
#    key, so registering under a fresh key per object means the deploy cannot pay for itself:
#    `preCharge: insufficient funds (0 < 1000000)`. `rho:registry:insertArbitrary` mints a fresh URI
#    with no key, so the node's own funded key signs.
#  * **A tuple pattern is exact.** `for (@(_, root) <- cap)` matches a 2-tuple and nothing else, and
#    an ERTP kit's reply is `(brand, mint, issuer)` — so the deploy fell through the pattern and
#    answered *nothing at all*. The pattern is now built from the shape the reply actually had.
#  * **A tuple does not cross as a bare record.** Syrup records are labelled, and the
#    label must be a symbol, string or byte string; `(true, 0)` encoded to a record labelled `true`,
#    which Endo refused outright:
#    `Unexpected type "boolean", Syrup record labels must be strings, selectors, or bytestrings`.
#    The Python suite never sent such a tuple, so only the second oracle could find this.
#    **Superseded 2026-10-06 by Law 59 (AUDIT C226):** the intermediate form this run then used, a
#    bare Syrup *list*, is also wrong — a list does not match a contract's `(brand, value)` pattern.
#    A tuple crosses as OCapN's **tagged** value, `<desc:tagged 'rho:tuple' [fields…]>`.
#
