   The peer counts are the **star topology this devnet starts**, not a connection that dropped: `up`
   gives each validator `--bootstrap rnode://…@devnet-bootstrap` and no other peer (`tools/devnet.sh`,
   the validator loop), so each knows one, while the bootstrap knows the three that dialed it. That is
   read from the start command rather than inferred from the counts — the counts alone would not
   distinguish the topology from a peer that went away.
